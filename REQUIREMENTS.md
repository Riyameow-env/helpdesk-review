# Требования к учебному модулю
Область: функции Python, хранение в памяти одного процесса. Веб-интерфейса, базы данных и настоящей авторизации нет. user — уже установленный идентификатор вызывающего пользователя. В практике передаются строки, целочисленные id и списки строк tags. Проверка остальных типов вне области задания.

- R1. create_ticket создаёт заявку со статусом open. Идентификаторы — уникальные последовательные целые числа от 1 после reset.
- R2. title сохраняется без пробелов по краям. Длина после strip — от 1 до 80 включительно. Иначе ValueError, состояние и счётчик не меняются.
- R3. user после strip непустой, сохраняется в очищенном виде. Иначе ValueError, состояние не меняется.
- R4. list_tickets(user) возвращает только заявки указанного пользователя. Если заявок нет, возвращается пустой список. user сравнивается после strip.
- R5. close_ticket(id) закрывает заявку по полю id и возвращает True. Другие заявки не меняются. Если id отсутствует — False без изменения состояния. Повторное закрытие существующей заявки возвращает True.
- R6. closed_share возвращает процент закрытых заявок от 0 до 100. При пустом списке — 0.0.
- R7. tags принадлежат конкретной заявке. Изменение переданного списка или результатов create_ticket/list_tickets не меняет внутренние данные. Результаты являются независимыми копиями, включая tags.
- R8. reset удаляет все заявки и начинает нумерацию заново с 1. Обращение к внутренней переменной tickets извне не является частью публичного контракта.

Критерии сопровождения: понятные имена, отсутствие ненужных импортов, ясный контракт функций, воспроизводимые инструкции запуска. Их нарушения описываются отдельно от R1–R8.
