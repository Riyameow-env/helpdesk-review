# Чек-лист ревьюера

Проверка `helpdesk.py` на соответствие `REQUIREMENTS.md`.
Отметки: `[ ]` — не проверено, `[x]` — выполнено, `[!]` — нарушено.

## R1. Создание заявки, id от 1

- [x] `create_ticket` создаёт заявку со статусом `open`
- [x] id — целое число
- [x] id начинаются с 1 после `reset`
- [x] id последовательные: 1, 2, 3...
- [x] id уникальны (нет повторов)
- [x] после `reset` нумерация начинается заново с 1

## R2. title — strip, длина 1..80, атомарность

- [!] `title` очищается от пробелов по краям (`strip`)
- [!] сохранённый `title` — уже очищенный
- [!] длина после strip ≥ 1
- [!] длина после strip ≤ 80
- [!] при нарушении — `ValueError`
- [x] при `ValueError` новая заявка не добавляется
- [x] при `ValueError` счётчик id не увеличивается
- [x] при `ValueError` другие заявки не меняются

## R3. user — strip, непустой, сохраняется очищенным

- [!] `user` очищается от пробелов по краям
- [!] сохранённый `user` — уже очищенный
- [!] `user` после strip непустой
- [!] при нарушении — `ValueError`
- [!] при `ValueError` состояние не меняется

## R4. list_tickets — фильтр по user

- [!] возвращает **только** заявки указанного пользователя
- [!] чужие заявки не попадают в результат
- [!] сравнение `user` идёт **после** strip с обеих сторон
- [x] если заявок нет — возвращается пустой список `[]`
- [x] возвращается непустой список, а не `None`
- [!] результат — новый список, а не ссылка на внутренний

## R5. close_ticket — поиск по полю id

- [!] поиск идёт по полю `id`, а не по индексу списка
- [x] успешное закрытие возвращает `True`
- [x] закрытая заявка получает статус `closed`
- [x] другие заявки не меняются
- [x] отсутствующий id → `False`
- [x] при `False` состояние не меняется
- [x] повторное закрытие существующей заявки → `True`
- [x] повторное закрытие не ломает статус

## R6. closed_share — процент 0..100

- [x] возвращает число от 0 до 100
- [!] при пустом списке — `0.0`
- [!] `0.0` именно float, не int
- [x] 100% — все заявки закрыты
- [x] 0% — ни одна не закрыта
- [!] нет `ZeroDivisionError` при пустом списке
- [x] считает по всем заявкам

## R7. tags — изоляция

- [!] переданный `tags` копируется при создании заявки
- [!] изменение входного списка после `create_ticket` не влияет на заявку
- [!] результат `create_ticket` — независимая копия
- [!] изменение `tags` в результате `create_ticket` не влияет на внутренние данные
- [!] результат `list_tickets` — независимые копии
- [!] изменение `tags` в результате `list_tickets` не влияет на внутренние данные
- [!] два вызова `list_tickets` возвращают разные объекты tags
- [!] нет мутабельного аргумента по умолчанию (`tags=[]`)

## R8. reset — очистка и сброс нумерации

- [x] `reset` удаляет все заявки
- [x] `reset` сбрасывает id на 1
- [x] после `reset` следующий id == 1
- [x] тесты не обращаются к `tickets` напрямую (по R8 — не контракт)

## Критерии сопровождения (отдельно от R1–R8)

- [x] имена функций, переменных, аргументов — говорящие
- [!] нет неиспользуемых импортов
- [!] контракт функций ясен: что принимает, что возвращает, какие исключения
- [!] есть докстринги или комментарии, объясняющие поведение
- [x] инструкции запуска воспроизводимы из корня проекта
- [x] нет лишних зависимостей (внешних библиотек)
